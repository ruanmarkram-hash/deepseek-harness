# Agent Note: 以配对为先的移动端预览

Status: implemented

[English](2026-08-20-mobile-pairing-first-preview.md) | 中文

## 问题

在相机捕获、加密传输和桌面端批准的接线尚未存在时，移动端壳需要让无账户桌面配对模型可被理解。通用的断开连接设置行会隐藏安全模型，或让人误以为粘贴配对代码即可连接手机。

## 决定

`apps/mobile/App.tsx` 通过 `@deepseek-ai/dsh-pairing-protocol` 接受手动粘贴的桌面 bootstrap，在校验后清除原始值，并且只为预览保留非秘密的本地摘要。它映射过期、版本、能力和格式错误，而不回显 payload 或中继 token。

该流程显示本地请求审核以及必须等待桌面端接受的显式阻塞状态。越过等待状态的唯一入口标记为视觉上的已配对会话壳预览，它不渲染远程会话，也不改变配对状态。应用不包含 WebSocket、中继、密码学、相机、凭据或计算机使用代码。

移动端展示把允许的操作固定为读取会话、实时订阅、向已有会话输入文本以及取消 turn。应用将计算机使用、批准、文件、凭据、workspace 与设置变更、附件和创建会话列为桌面端专属。

## 考虑过的替代方案

**成功配对模拟。** 已否决，因为看似接受手机的本地转换会掩盖桌面端确认要求。

**在传输存在前加入相机依赖。** 已否决，因为粘贴可在不扩大原生权限或应用供应链的前提下使用同一 QR 解析器。

**通用远程控制界面。** 已否决，因为配对后移动端仍是受限会话客户端，而不是桌面端的权威。

## 后果

配对体验可在中继集成前完成审阅，同时保留敏感代码和桌面端专属边界。下一个移动端传输切片会以安全本地存储、平台密码学、加密中继 I/O、重连处理和经桌面端确认的连接状态取代视觉预览。
