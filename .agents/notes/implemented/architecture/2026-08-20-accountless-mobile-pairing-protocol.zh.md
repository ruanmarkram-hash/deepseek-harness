# Agent Note: 无账户加密移动端配对词汇

Status: implemented

[English](2026-08-20-accountless-mobile-pairing-protocol.md) | 中文

## 问题

DSH 桌面端是本地会话与特权能力的受信任所有者，而手机需要一个高效的远程会话界面，不能依赖用户账户、局域网假设或让中继看到明文。临时 QR 字符串和中继 JSON 会使 Electron、Expo 与中继之间的过期、能力准入和重放行为不一致。

## 决定

`packages/mobile/pairing-protocol` 为桌面签发的短时 QR bootstrap 与不透明加密中继帧提供第一版、平台无关的解析器。QR 使用唯一规范的 `dsh-pairing:v1:` base64url JSON 形式，在五分钟内过期，用公开且不透明的 id 标识 rendezvous 与桌面，并携带短时中继 bearer token。该包校验 token 格式，但绝不记录或持久化它。

中继只限于传输 token 与路由决策。Electron 宿主仍是信任锚：它创建 bootstrap、确认设备、批准固定的移动端能力允许列表并负责撤销。Expo 客户端和 Electron 宿主提供经过审计的平台密码学，并通过中继发送不透明密文。共享包刻意不包含密钥生成、加密、解密、网络 I/O 或秘密存储。

中继信封使用一个版本、不同的发送与接收 id、有界不透明密文字段，以及每个方向的连续序列。接收方拒绝重复、跳过、无效和已耗尽的序列，而不会静默重排。第一版只允许读取／订阅会话，以及向已有 turn 发送／取消；它排除计算机使用、文件系统、凭据、workspace 管理、管理操作和创建会话。

## 考虑过的替代方案

**由 Supabase 支持的账户身份。** 已否决，因为产品需要独立、无账户的设备通道，而不是另一个用户数据库或共享产品后端。

**中继可见的会话 JSON。** 已否决，因为能够检查会话内容的中继会成为数据所有者，并增加 prompts、输出和操作上下文的暴露。

**通用远程控制能力。** 已否决，因为手机是受限会话客户端。即使加密配对成功，桌面专属权限仍保留在桌面上。

## 后果

Cloudflare Durable Object 实现可以路由并验证一次短时配对，而不会成为明文存储。它必须只校验自己的 token 与路由状态，及时使其过期，并且不解释地中继密文。Electron 与 Expo 现在共享精确的版本、解析器、能力和重放规则，但部署仍必须提供经过审计的密码学、安全 token 存储、桌面确认、设备撤销、重新连接恢复和真正经过认证的会话网关。
