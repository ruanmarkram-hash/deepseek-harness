# Agent Note: Mobile disconnected session preview

Status: implemented

[English](2026-08-20-mobile-disconnected-session-preview.md) | 中文

## Problem

移动客户端原本只有一个网关地址表单，因此没有建立 DSH 伴侣应用所需的以会话为中心的交互。把地址表单当成连接流程，也会暗示在移动网关存在之前，应用已经能够认证用户、获取会话或持有桌面端权限。

## Decision

`apps/mobile/App.tsx` 提供原生、以会话为中心的本地预览，其中包含会话浏览器、沉浸式对话界面、输入区域和设置入口。明确标记的示例行和消息展示信息层级，但绝不被描述为已同步的会话数据。对话输入区域会为布局和键盘行为保存内存中的草稿；其操作会打开配对设置，而不是发送请求。

配对设置会报告断开连接的状态，并说明已认证的移动网关尚未实现。应用不会收集网关地址、二维码、帐户令牌或凭据，不会发起网络请求，不会在进程关闭后保留草稿，也不会声称已配对桌面设备。计算机使用和 macOS 隐私权限仍仅限桌面端。

## Alternatives considered

**保留网关地址表单。** 它提供了一个配置字段，却没有会话导航，并会让用户期待产品无法安全提供的连接路径。

**只显示空会话列表。** 空状态是如实的，但在传输层存在之前，无法让产品评估全屏对话与输入体验。带标签的本地示例保留了这种清晰性。

**添加从手机直连桌面的功能。** 直连路径会引入新的认证、可达性、会话策略和凭据生命周期责任。已认证网关仍是这些责任的所有者。

**持久化预览草稿或配对输入。** 持久化会让未配对的本地预览看起来像帐户或连接状态。预览只保留打开进程期间的 UI 状态。

## Consequences

移动应用可以作为会话伴侣进行评估，而不会悄悄执行网络操作或模糊桌面权限。未来网关可以用已认证的会话状态替换带标签的预览数据源，并将输入绑定到经批准的传输，但必须保留明确的仅桌面端计算机使用边界。当前示例内容有意不持久化，不能恢复工作。
