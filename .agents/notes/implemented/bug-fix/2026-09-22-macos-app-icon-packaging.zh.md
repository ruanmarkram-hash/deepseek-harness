# Agent Note: 共用 macOS 应用图标打包

Status: implemented

[English](2026-09-22-macos-app-icon-packaging.md) | 中文

## 问题

Host 缺少声明的图标资源。Desktop 的 ICNS 在大画布角落显示很小的标记，因此文件尺寸有效并不代表应用图标可用。启动器搜索中无关的构建副本使这些外观难以区分的应用更难识别。

## 决策

[图标生成器](../../../../scripts/macos-icons.ts) 在白色圆角底板上的居中视口中复用规范 SVG 路径。Desktop 和 Host 使用同一 ICNS；Host 在外层应用签名前声明并复制该文件。打包时将提交的资源与生成器结果比对，并检查每个标准及 Retina 图像中可见蓝色标记的占用面积、中心、留白及像素尺寸。

Desktop 使用打包的原生图标，不会用加载为 Electron NativeImage 的 SVG 覆盖它。HTML 配对页面保留独立的 SVG 渲染路径。

## 考虑过的替代方案

**缩放旧位图。** 这会保留角落位置并放大原有缺陷。从 SVG 渲染可避免累积的栅格质量损失。

**分别维护 Host 和 Desktop 图稿。** 两个应用使用同一个现有品牌标记。分别维护副本会增加漂移，却不能满足新的识别需求；名称已区分它们的角色。

**修补已安装的签名资源。** 这会使 Host 的代码封印失效。图标资源应在签名前装配，发布安装流程另行处理。

## 影响

仓库为已使用的 Sharp 版本新增直接开发依赖，并增加一个共用生成资产。PNG 预览保存在被忽略且不被索引的构建目录中，不会增加可启动的应用。定向回归检查会拒绝角落中的微小标记、偏离中心的标记、错误图像尺寸、缺失图像及截断容器。图标变更不会改变应用运行时、配对、身份、权限或凭据。
