# Agent Note: 移动端配对扫描确认

Status: implemented

[English](2026-09-21-mobile-pairing-scan-confirmation.md) | 中文

## 问题

相机会立即提交注册，而不会要求输入代码时提供的确认。相机回调可能在 React 提交忙碌状态之前重复触发，导致重复 offer。Relay 使用 HTTP 409 拒绝重复 offer，但手机将所有被拒绝的 offer 都归类为过期。因此，仅凭过期提示的截图无法确定实际 relay 响应，也无法证明发生了重复请求。

## 决策

扫描会验证并捕获一个代码，关闭扫描器，然后要求点击 **Pair with Host** 才会发送注册请求。同步保护独立于 React 渲染，将显式提交串行化。HTTP 状态决定本地定义的提示；relay 响应正文和配对凭据绝不出现在错误中。HTTP 404 表示代码不可用，可能已过期或被删除，而不直接断言过期。审批轮询超时与代码有效性分别处理。

## 考虑过的替代方案

**保留自动提交并加锁。** 这能防止重复请求，但仍保留扫描代码和手动输入代码之间令人意外的行为差异。

**将冲突视为成功的重试。** Relay 的冲突响应不能证明已有 offer 属于这部手机，因此静默继续会隐藏不确定状态。

## 后果

配对在扫描后需要一次显式点击。Host 仍要求本地指纹比对和批准。定向回归测试覆盖重复相机回调、并发提交回调、保护释放和安全的错误提示。原生相机交互和完整实体设备配对流程仍是单独的发布检查；单元测试通过并不能证明手机构建已部署或连接已建立。
