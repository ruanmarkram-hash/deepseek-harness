# Agent Note: 移动端断开连接提示

Status: implemented

[English](2026-09-23-mobile-disconnect-notices.md) | 中文

## 问题

手机在认证尝试后可能只显示连接已断开，隐藏先前的安全错误信息。该状态本身无法区分后台清理、页面卸载或显式断开，也不能证明实际由哪个 iOS 事件引发中断。

## 决策

移动客户端对每种原因执行相同的安全清理后，发出固定的本地断开原因和待处理尝试的阶段。独立的进程内展示状态保存这些事实与先前的安全错误。页面所有权检查防止迟到的回调覆盖新页面的提示。显式尝试、成功和 Forget 会清除提示。首页与两个面板使用同一连接操作投影；Connect 在认证前打开连接面板。

后续清理没有活动尝试时，会保留已有中断，而不以信息更少的原因替换。Forget 在等待钥匙串删除前同步清除提示，因此其迟到完成不会抹去新的后台提示。每次调用使用独立令牌表示操作所有权：已取消的操作允许显式替换，且只有当前令牌能够解除重复点击限制。原生存储串行化保持不变。

操作取消信号阻止待处理的邀请恢复在进入后台、页面卸载或 Forget 后启动认证。前台事件仍不执行操作。断开后的重试恢复持久保存的 Host 签发配置，并使用 connect，因为清理已移除客户端配置。观察者异常只产生固定警告，不会阻止清理结果报告或破坏连接控制流程。

现有[阶段诊断](2026-09-23-mobile-connection-stage-diagnostics.zh.md)与[初始化重试和在场会话复用](2026-09-23-mobile-bootstrap-retry-and-presence.zh.md)决策仍有效：它们的失败阶段、时限、已认证 epoch 最终性和原生身份生命周期均保持不变。

## 考虑过的替代方案

**断开后让 transport 保持错误状态**会混淆展示与连接权限，并可能在配置已被清除后让重试进入 reconnect。

**在 Face ID 期间抑制或延迟后台清理**会假定尚未证实的触发原因并延长认证生命周期。记录本地原因可以在不改变安全规则的前提下提供证据。

**持久保存诊断历史**会为临时调查增加持久数据。进程内提示可维持页面连续性，而不存储标识符、凭据或帧。

## 影响

界面展示安全的清理证据，而协议消息、原生认证、密钥和持久 epoch 保持不变。进程终止会丢失提示。后台原因报告 JavaScript 收到的事件，并不意味着用户确实离开了应用。实际的 Face ID 后触发原因仍未证实。

## 验证

真实移动客户端与加密 relay 测试通过内存平台适配器使用真实原生状态存储，对错误保留、取消所有者在场认证和显式重试成功进行快照验证。它们验证迟到认证不会创建 socket、返回前台不执行操作、确切下一 epoch 的持久化、请求权限已清除、所有断开原因以及观察者异常隔离。投影与操作测试覆盖失效页面租约和已取消的原生读取。真实 iOS 生命周期与 Face ID 仍属于发布验证项。

挂载 App 的测试将原生控件替换为 DOM 元素，执行实际生命周期订阅、按钮处理程序和提示所有权逻辑。它们验证握手阶段进入后台后卸载并重新挂载，以及延迟 Forget 期间进入后台。原生读取取消后再显式替换的测试，在不绕过存储串行化的前提下固定操作令牌的所有权规则。
