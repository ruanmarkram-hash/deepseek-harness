# dsh-remote-host-app

English | [中文](README.zh.md)

`dsh-remote-host-app` is the signed persistent macOS owner for one DSH Host remote boundary. It is separate from the Electron Desktop renderer. It validates its own code signature and never exposes a Keychain service, identity operation, token, TCP endpoint, HTTP endpoint, UNIX socket, or other public listener.

The assembled `DSHHost.app` contains a signed native runtime child and a sealed `DSHRemoteHostKeychain.xpc` bundle. Both native executables validate their enclosing signed bundle before reading a resource that controls trust. The Host app checks the nested runtime's exact signed requirement and canonical bundle-relative path before it launches the runtime over one dedicated socket descriptor. `posix_spawn` closes every other open child descriptor before exec; the runtime sets close-on-exec on its sole private descriptor and closes every unrelated descriptor. The Host writer sets `SO_NOSIGPIPE`, and it clears and closes the channel then reaps the child on malformed data, overflow, EOF, or child shutdown.

Release artifacts run only from a canonical, non-symlinked `DSHHost.app` at `/Applications` when root-owned or at the current user's `~/Applications` when owned by that user. The logged-in owner is trusted to replace a user-level installation. Every accepted installation still requires a strict whole-app code seal, the sealed designated Host requirement, embedded manifests and digests, valid nested-code requirements, no extended ACL, and no group or world writer anywhere inside the app.

The native relay owner foundation has typed V3 route and provisioning credentials, a Host-code-requirement Keychain store, exact fixed-origin request construction, and lifecycle states. `RelayEnrollmentLifecycle` is the only production completion path: it requires local confirmation, accepts the private runtime's `device.enrolled` receipt as the sole source of the Host and device enrollment ids, gets an accepted relay provision result, stores the full route credential in signed-native storage, and only then returns a phone-safe invitation. It rejects a changed public tuple or a replayed receipt. Before a relay create attempt it records a native-only pending credential; an uncertain create or failed compensation remains invitation-free until idempotent cleanup removes that record. Revoke records durable cleanup intent before its remote request. Any ambiguous revoke result or local cleanup failure suppresses the invitation; recovery repeats the idempotent remote deletion before removing either native credential record. After strict Host validation and a ready private runtime, startup constructs `RelayHostPairingComposition` with a typed public-identity XPC call, a typed 32-byte static X25519 agreement operation, and a fixed FD198 `device.enroll`/`device.enrolled` exchange. The helper receives no profile selector, generic operation, token, or private key, and its caller can use the returned secret only for immediate native KDF work. This construction sends no relay request and does not accept or confirm a device. The invitation contains route coordinates, client role token, those runtime-issued enrollment ids, the pinned Host agreement key, and the expected device signing and agreement keys. The composition can emit only public `route.upsert`, `route.revoked`, `device.enroll`, and `device.enrolled` Remote Wire facts, never a Host token or private key. A production `RelayURLSessionRouteProvisioner` is constructed only when a separate sealed `RelayProvisioningActivation.plist` is present, enabled, and pins the running Host requirement. Without it, local confirmation remains pending and touches neither runtime enrollment nor a route. The app therefore still has no automatic provisioning action, WebSocket activation, QR presentation, Node gateway bridge, public network endpoint, or live pairing action.

The offline Host V3 transport seam accepts only injected sockets for deterministic testing. Its Keychain-backed epoch ledger uses a kernel-held, crash-reclaimable Host-owner lease plus short serialized state transitions to reserve the active route's exact next epoch before a socket starts, atomically finalizes it only after the authenticated device `confirm`, then emits encrypted `receipt`; a durable next reservation reconciles a lost receipt with the prior epoch without skipping the next epoch. Revoke first installs a durable tombstone that rejects later claims and reservations, then fences the active socket; the socket rechecks that tombstone immediately before and after it starts and before encrypted traffic, while recovery retains denial until native cleanup completes. It binds every V3 flight to the exact route, generation, epoch, device and enrollment-incarnation tuple; executes `hello → welcome → ready → finish → ack → commit → confirm → receipt`; and derives the Host-side `SS, e-S, S-e, ee` X25519 material with the protected static agreement seam, canonical hello/welcome HKDF salt, `dsh-remote/v3/3dh` info, and directional keys. It authenticates each encrypted flight with Noble-compatible canonical per-message AAD, races both reads and writes against injected-clock deadlines, zeroizes directional/sealer material on teardown, and closes on malformed input, timeout, EOF or failed authentication. `RelayUnstartedURLSessionTaskFactory` can construct a suspended task only for `wss://dshrelay.rulabs.dev/v3/routes/:routeId/connect` with exactly `dsh-remote-v3` and the Host token subprotocol. It has no `resume` or activation API. The reproducible `generate-v3-3dh-fixture.mjs` checks a fixed Noble V3 reference fixture; the transport remains offline-only and must not be connected to a real relay without an explicit activation review.

## Sealed Node gateway release artifact

The signed Host currently starts only its native enrollment runtime. It never resolves `node` from PATH, a shell, an environment variable, or an app-provided path. A future V3 gateway release must be assembled with both `--sealed-gateway-node` and `--sealed-gateway-entrypoint`; supplying one without the other is rejected.

The inputs must be an externally produced macOS-arm64 Node release binary and one self-contained, compiled `dsh-remote-host-v3.mjs` file. The packager rejects symlinks, TypeScript/package trees, ESM imports, dynamic imports, `require`, `process.env`, and child-process access. It signs the copied Node binary, records its strict designated requirement and SHA-256 plus the entrypoint SHA-256 in `Contents/Resources/GatewayRuntime/GatewayRuntimeManifest.plist`, then the outer Host signature seals that manifest and both artifacts.

`scripts/build-sealed-gateway-entrypoint.mjs --output /absolute/dsh-remote-host-v3.mjs` reproducibly compiles the existing V3 fixed-FD contract into a dependency-closed preflight artifact. It accepts only the existing `--private-fd 198` argument and verifies that descriptor is a socket. It intentionally does not mount Cordis, provision a route, open a relay, or proxy a session. The full `remote-host-v3` coordinator is not currently eligible for the sealed bundle because its transitive Cordis/API stack contains ambient-environment reads, dynamic module loading, optional `require` paths, and child-process code.

No current package output satisfies a live gateway release contract, and no vetted distributable Node runtime has been supplied. Therefore the Host stays fail-closed and does not activate a Node gateway. Any future native launcher must first load the sealed manifest from its signed bundle, verify both fixed resource paths, both digests, and the Node code requirement, then exec only that embedded Node with the fixed `--private-fd 198` argument, an empty environment, and all other descriptors closed. It must not receive a route credential, Host private/agreement key, provisioning token, or a generic RPC surface.

## Assemble

```sh
native/remote-host-app/scripts/assemble-host-owner.sh \
  --signing-identity "Apple Development: Name (TEAMID)" \
  --output /absolute/path/to/DSHHost.app
```

The command creates a signed Host app, embeds the signed XPC service under `Contents/XPCServices`, derives its exact designated requirement, seals that requirement back into the Host app, and verifies nested code signatures. It does not install a LaunchAgent, start the app, provision Cloudflare, or pair a device.

When running, the Host exposes one local macOS menu action: **Import iPhone enrollment offer…**. It reads one bounded JSON file chosen by the person at that Mac, accepts exactly the four public identity fields (`deviceId`, `label`, `signingPublicKey`, `agreementPublicKey`), displays the complete SHA-256 fingerprint and label, and requires a separate local confirmation click. This build records only a pending candidate after that click. It does not invoke lifecycle completion, provision a route, create a token, open a socket, or pair the phone.

`scripts/verify-private-runtime-smoke.sh` assembles temporary signed Host owners, rejects a direct runtime launch without its private descriptor, rejects a client not signed by the selected identity, verifies the full code seal, proves a changed XPC authorization resource invalidates that seal, rejects generic helper operations in favour of typed public-identity open, proves the sealed Host survives inert supervisor-ready startup, and verifies the owner fails closed and reaps a runtime child that exits.

## Private runtime protocol

The native runtime child is a narrow placeholder for the future packaged DSH runtime bridge. It receives no listening socket, accepts no standard-input or standard-output protocol, and has no configuration lookup. It receives one app-created descriptor at a fixed private file descriptor number, with close-on-exec set before it handles messages.

Remote Wire is a fixed length-prefixed record format: `u32 body length`, `u8 kind`, `u16 UTF-8 metadata length`, bounded metadata, and an opaque payload. Records are capped at 8 MiB and metadata at 16 KiB. The only recognized record kinds are `runtime.ready`, `route.upsert`, `route.revoked`, `epoch.begin`, `epoch.begun`, `epoch.commit`, `epoch.committed`, `connection.open`, `connection.frame`, `connection.closed`, `connection.send`, `connection.close`, `host.stopping`, `device.enroll`, and `device.enrolled`. `device.enroll` is Host-to-runtime with exact public `{ "deviceId", "label", "signingPublicKey", "agreementPublicKey" }` metadata and no payload; `device.enrolled` returns that tuple plus `{ "deviceEnrollmentId", "hostEnrollmentId" }`, also with no payload. Native enrollment and relay-flight JSON scans reject duplicate member names before Foundation decodes them. A native `route.revoked` record has exactly `{ "deviceId" }` metadata, matching the inherited TypeScript consumer. Unknown kinds, malformed lengths, invalid metadata, overflows, an out-of-order `runtime.ready`, and EOF fail closed. The foundation recognizes this vocabulary only: it does not implement generic RPC, identity, token, route, relay, or socket operations.

The current runtime sends `runtime.ready` and accepts only exact `device.enroll` records. It durably records the public enrollment tuple in native Keychain storage before replying with one `device.enrolled` record; it has no token, route, signing, generic operation, listener, or network API. The signed Host never sends `device.enroll` without a later explicit local confirmation, so ordinary startup remains inert. An unsigned `dsh web` source process is not a permitted private-wire participant.

## ChaCha20-Poly1305 interoperability fixture

`SodiumXChaChaBridge` exposes only authenticated RFC 8439 ChaCha20-Poly1305 encrypt, decrypt, and secure-zeroize. SwiftPM links the tracked macOS-arm64 static archive only after its hardcoded SHA-256 and architecture checks pass; ignored build output and a preparation marker are never link authorization. `scripts/prepare-sodium-xchacha.sh` verifies the vendored official Minisign signature and SHA-256, enforces arm64, records the compiler, Xcode, SDK, flags, signature, and source digests, and requires its zero-timestamp rebuild to reproduce the tracked archive digest. `scripts/verify-sodium-preparation-smoke.sh` proves that a paired substituted archive and marker cannot satisfy SwiftPM and that an absent Minisign verifier fails closed.

The prebuilt archive is intentionally limited to macOS arm64. A signed release must still verify the complete app code seal after assembling all nested code; this source-level digest cannot defend a developer checkout against an active same-user process that can replace both the archive and `Package.swift` before compilation.

The checked-in `xchacha-v3-noble.json` fixture records an exact 32-byte key, 12-byte nonce, AAD, plaintext, and ciphertext generated by the already-pinned RFC 8439 `@noble/ciphers@2.2.0` primitive used by `packages/mobile/remote-relay-protocol`. From the repository root, `node native/remote-host-app/scripts/generate-xchacha-noble-fixture.mjs` resolves that exact mobile dependency and reproduces it for review. Swift tests require byte-for-byte equivalence and reject modified ciphertext and AAD. The zeroization test verifies that the caller-owned mutable buffer is overwritten before the caller releases it.

Production encryption uses a frame sealer, not raw encryption with a caller-supplied nonce. Each sealer creates one `SecRandomCopyBytes` 4-byte prefix, emits a monotonic big-endian 64-bit suffix for each frame, and fails closed after the final suffix. A Host must use one sealer per directional session key and discard it with that key; nonce prefixes and counters are never restored or shared across a new session.
